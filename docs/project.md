# FOI RAG — Project Documentation

A RAG (Retrieval-Augmented Generation) system for querying Camden Council Freedom of Information request PDFs. Built as a learning project.

---

## Scope

A local tool that lets you ask natural-language questions against 40 Camden Council FOI PDFs and get cited, grounded answers. Includes an evaluation harness to measure and track quality over time.

**What it does:**
- Ingests FOI PDFs → extracts text → chunks → embeds → stores in pgvector
- Answers queries using vector search + LLM reranking + Claude Sonnet generation with inline citations
- Evaluates retrieval quality using a synthetic golden dataset (MAP, MAR, NDCG, Precision/Recall/F1 at k)
- Streamlit UI with Ask, Observability, Evals, and Performance tabs

**What it is not:**
- A production service
- A multi-user system
- A general-purpose search engine

## What's built

### Core RAG pipeline
- 40 FOI PDFs ingested → 97 chunks, avg 350 tokens
- Vector search (cosine, HNSW index) → Claude Haiku rerank → Claude Sonnet generate with `[SOURCE N]` citations
- Query logging to `query_logs` table

### FastAPI (`src/api/main.py`)
Four endpoints:
- `GET /health`
- `POST /query` → full pipeline + stores trace in `filters` JSONB column
- `GET /logs/{query_id}` → returns full trace (embedding, retrieval candidates, rerank candidates, prompt, response)
- `GET /documents` → lists all indexed documents

Run:
```bash
docker compose up -d db
uv run uvicorn src.api.main:app --reload
```

### Golden dataset (`eval_data/synthetic_chunk_query_pairs.csv`)
291 rows — 3 queries per chunk (very_relevant=4, medium_relevant=2, low_relevant=0).
Generated by `scripts/generate_ground_truth.py` using Claude Sonnet.

Regenerate:
```bash
uv run python3 scripts/generate_ground_truth.py
# or test on 5 chunks first:
uv run python3 scripts/generate_ground_truth.py --limit 5
```

### Eval metrics (`src/retrieval/metrics.py`)
- `load_golden_dataset(csv_path)` — loads CSV, validates columns, normalises query text
- `evaluate_query_ranking(query_text, predicted_chunk_ids, golden_df, ks, relevant_threshold)` → `QueryEvalResult`
  - Precision@k, Recall@k, F1@k (at k=1,3,5,10)
  - NDCG@k (rewards ranking relevant chunks higher)
  - MAP (Mean Average Precision)
  - MAR (Mean Average Recall)

### Streamlit UI (`scripts/app.py`)
```bash
uv run streamlit run scripts/app.py
```

Four tabs:

| Tab | What it shows |
|-----|--------------|
| **Ask** | Query input + answer + citations |
| **Observability** | Full pipeline trace: embedding preview, retrieval table with scores, rerank table, prompt sent, answer |
| **Evals** | MAP/MAR/NDCG metrics + P/R/F1@k table against golden dataset |
| **Performance** | Retrieval counts, models used (per-step timing coming next) |

**Note on Evals tab:** must use a query that exists in the golden dataset (exact text match). The eval measures retrieval quality — whether the right chunks were found and ranked well.

**Note on synthetic eval scores:** scores are optimistically high because queries were generated from the chunks themselves. Use for regression testing (detecting drops), not as absolute quality measures.

## What's next

### Immediate

1. **Per-step latency in the API** — add `time.perf_counter()` timing around embed, search, rerank, generate steps; store in `filters` trace; display in Performance tab
2. **Token counts + cost** — return token usage from OpenAI/Anthropic responses; calculate estimated cost per query
3. **Unit tests** (`src/tests/`) — test chunker, metadata loader, metrics pure functions

### Stretch goals

- **Dockerfile** — containerise the API so `docker compose up` starts everything
- **Hybrid search** — combine pgvector similarity with PostgreSQL full-text search (`tsvector`)
- **Query expansion** — Claude rewrites the question into multiple variants before retrieval
- **Conversational retrieval** — maintain history so follow-up questions resolve references correctly
- **ANN vs brute-force comparison** — compare HNSW approximate search against exact vector search
- **Corpus expansion** — ingest more PDFs, test scaling behaviour
- **Regression baseline** — save eval scores to `logs/baseline.json`, flag regressions on re-run

### Future / out of scope for now

- Multi-user authentication
- Cloud deployment
- Real-time ingestion of new FOI requests
- Fine-tuned embedding model on Camden data
